## 二、信息架构（IA）与页面体系

### 2.1 站点地图（实测导航结构）


**设计要点**：宜家采用**"商品类目树 + 房间空间"双维度导航**——用户既可以按"我要买什么"（商品）浏览，也可以按"我要布置哪里"（房间）浏览；再用**系列**（KALLAX/EKTORP…）做第三条商品组织线索。这三条线索贯穿全站。

## 三、视觉设计体系

- **色彩**：宜家蓝（约 #0058AB）+ 黄（#FFDB00）用于 Logo 与品牌触点；界面主体为**白底 + 浅灰区块**，文字近黑；促销标签用红色系（大减价）
- **字体**：中文无衬线系统栈（全球设计系统 SKAPA 规范，推断）
- **导航模式**：顶部固定导航 + "所有商品"打开**全屏 Mega Menu**（汉堡式类目树）+ 面包屑 + 页脚胖导航（5 栏链接矩阵）
- **商品卡片**：圆角图片卡片 + 系列名加粗 + 规格描述 + 价格大号分体排版 + 角标（热卖/新品/即将下架）+ "+N" 多变体提示 + "对比"复选框
- **图标**：线性 SVG 图标体系（退货政策、电钻、设计服务等）
- **图片策略（实测特色）**：
  - PLP 提供**"商品图（白底）/ 场景图（生活场景）"一键切换**
  - PDP 画廊含场景图、白底图、视频（hls.js 流媒体）、3D 展间
  - 图片走独立 CDN，多规格后缀（`…_s5.jpg`），按上传日期分目录
- **响应式**：移动端首页使用**独立 CMS 页面 ID**（mobileHomePageZhId）→ "自适应 + 服务端设备分流"混合策略；小程序/App 为独立端

## 四、前端设计逻辑

1. **技术形态**：Nuxt 3 SSR 同构，首页 HTML 直出（约 151KB），客户端 hydrate；SEO 友好（canonical、og 标签、语义化拼音 slug URL、robots 精细屏蔽）
2. **路由结构**：
   - `/cn/zh/` 首页｜`/cn/zh/cat/{拼音slug}-{类目ID}/` 类目｜`/cn/zh/p/{拼音slug}-{货号}/` PDP（货号 xxx.xxx.xx 全局唯一键）
   - `/rooms/{room}/`、`/ideas/`、`/campaigns/`、`/new/`、`/ikea-family/`、`/stores/`、`/customer-service/…`
3. **核心组件清单**：GlobalHeader（公告条/搜索/MegaMenu）、CategoryCard、ProductCard（标签/价格/对比/+N 变体）、FilterPanel、SortBar、ViewToggle（商品图/场景图）、PDPGallery（图/视频/3D）、VariantSelector、LocationPicker、StoreStockChecker、BuyBox、ServicePromiseBar、TabsSection、ReviewCard、RecommendCarousel、FooterLinks、ChatWidget、LeadFormModal（设计预约线索）、CookieConsent（CMS 配置驱动）
4. **状态管理（推断）**：Pinia；购物车/收藏与 CIAM 登录态绑定（登录前本地、登录后云端合并）；定位存 cookie
5. **数据流**：`window.__NUXT__` 注入 SSR 首屏数据 → 客户端 hydrate → 后续交互走 BFF
6. **性能**：CDN 整页缓存 + 静态资源多域名分发 + modulepreload/preconnect + 图片懒加载占位 + 视频分片 + i18n 分包懒加载
7. **埋点与风控**：GrowingIO 全埋点 + 自建事件上报 + DoubleClick；极验验证码用于登录/注册/下单

## 五、后端设计逻辑（行业通行架构推断，与实测 API 前缀吻合）

### 5.1 商品域
- **PIM 商品信息管理**：SPU = 系列/款（KALLAX 搁架单元），SKU = 颜色×尺寸变体；**货号 xxx.xxx.xx 为全局主键（实测）**；组合装 = 多 SKU 捆绑
- **类目树**：商品类目树（≥3 级）+ 房间维度 + 系列维度三线索；筛选聚合字段实测：座位数/分类/颜色/尺寸/价格
- **属性体系**：尺寸/承重/材质/保养/设计师/产地/安全警示/环保材料——推断为按类目配置的**属性模板**
- **包装数据**：每商品多包裹记录（长宽高/净重/容量），用于**运费试算与快递/货车配送分流**（FAQ 实测：306 城包裹配送 + 货车配送）
- **价格与促销引擎**：标准价/会员价/档期大减价/"更低价格"标签；满额返券
- **库存**：**区域仓 + 门店库存双轨**——PDP"查询商场库存"、按定位校验配送可达性

### 5.2 内容域（CMS）
- 首页/移动端首页/页头/页脚/Cookie 弹窗/全局弹窗全部以**页面/资源 ID 配置下发（实测）** → Headless CMS + 运营位（slot）管理
- 灵感内容（/ideas/ 文章、创意图库、3D 样板间）、campaigns 活动页

### 5.3 交易域
- **购物车**：加入购物袋/立即购买双通道；购物车内加购增值服务（组装）
- **订单/支付**：下单 → 电子收银条 → 扫码自助开电子发票；分期付款；推断接入微信支付/支付宝/银联
- **履约**：配送到家（按地址+邮编试算）、门店提货（Click & Collect）、旧家具拆运、回购再售（逆向物流）

### 5.4 支撑域
- **搜索**：独立 `/api-search/`；关键词 + 筛选聚合 + 价格排序；已上线**生成式 AI 搜索与 AI 购物助手**（算法备案实测）
- **推荐**：常常一起买（关联规则）/ 热卖（销量榜）/ 猜你喜欢（个性化）三个推荐位实测
- **会员**：宜家俱乐部（个人）+ 企业会员双体系；积分、会员价、退换货 60 天→会员 365 天；CIAM 独立服务
- **评价/UGC**：晒单三维度评分 + 图文（推断审核后展示）
- **客服**：在线 IM + 400 热线 + 微信小程序工单

### 5.5 微服务划分（推断，与实测前缀吻合）
`Kong 网关` → 商品货架 `/api-product-shelf`｜搜索 `/api-search`｜CMS `/api-cms`｜CIAM `/api-ciam-host`｜客服 `/api-csh`｜价格促销｜库存｜购物车｜订单｜支付｜履约｜会员｜推荐｜评价｜门店｜**BFF 聚合层**；Envoy 服务网格做东西向流量。

### 5.6 缓存策略
- L1 Cloudflare 整页/静态缓存（s-maxage=900 实测命中）
- L2 BFF 聚合缓存（首页 CMS 内容、类目树）
- L3 Redis：价格/库存短 TTL、会话、购物车；CMS 长缓存 + 发布主动失效

## 六、对中小型项目的取舍启示

宜家官网是"重投入全链路"形态，但其设计中**可提炼的普适骨架**是：

1. **双维度导航**（商品类目 × 空间场景）+ 系列线索 —— 中小项目可低成本复刻
2. **CMS 运营位驱动的首页** —— 首页内容后台可配，而非硬编码
3. **SPU/SKU/变体三层商品模型 + 属性字典化** —— 支撑筛选聚合
4. **白底图/场景图双图策略** —— 同一商品两套视觉资产，体验提升显著
5. **SSR/SEO** —— 官网性质站点必须解决（宜家选 Nuxt SSR；中小项目可用预渲染替代）
6. **BFF 聚合接口** —— 首页一个接口出全部数据，前端体验与性能双赢
7. **设计服务线索收集**（预约弹窗）—— 家居行业官网的核心转化动作，比在线支付更轻

实际抓取的 URL：首页、`/cat/sha-fa-fu003/`、`/cat/products-index-index/`、KALLAX PDP、`/ideas/`、`/new/`、`/campaigns/`、`/customer-service/`（含 services）、`/stores/`、robots.txt 等共 14 个。
