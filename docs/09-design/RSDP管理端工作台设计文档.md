## 第一章 · 设计决策：为什么管理端用"现代极简"

### 1.1 管理端与用户端的本质差异

| 维度 | 用户端官网（style-a 暖调） | 管理端工作台（style-b 极简） |
|---|---|---|
| 使用者 | 消费者（逛、看、买） | 内部运营（录、审、配、跟） |
| 单次时长 | 分钟级 | 小时级，每天重复使用 |
| 核心诉求 | 氛围感、购买欲 | 效率、密度、准确性 |
| 信息形态 | 大图 + 少字 | 表格 + 编码 + 状态 |
| 色彩策略 | 暖调低饱和、促销赭石点缀 | 中性灰白、功能色极小面积 |

### 1.2 style-b 的三个设计支柱

1. **中性底，零情绪色**：`#F7F7F7` 灰白底 + 白卡 + `#1A1A1A` 墨字，界面本身"退后"，让数据成为主角；唯一功能强调色是赭石 `#C2622B`（与用户端促销赭石同源，保持品牌一家人）；
2. **等宽字体承载数据**：所有编号（RSPU 编码、任务号）、价格、耗时、统计数字一律 monospace——数字对齐即正确性可肉眼校验（如 `SF-WJ-002-L`、`12.4s`、`¥4,680`）；
3. **高密度表格优先**：管理端的核心组件是表格（vxe-table），卡片只用于"产品"这种有图实体；每屏信息量约为用户端的 3 倍。

### 1.3 为什么不是另一套花哨主题

现有管理端功能已经完整（39 个后端控制器、101 个测试类约 888 个测试支撑），问题只在视觉。style-b 的落地成本最低：**只换 tokens + Naive UI 主题覆盖 + 字体栈，组件和业务逻辑零改动**（详见第七章）。

## 第二章 · 设计系统（Tokens 完整规范）

### 2.1 色彩系统

| Token | 色值 | 用途 |
|---|---|---|
| `--bg` | `#F7F7F7` | 页面主背景 |
| `--card` | `#FFFFFF` | 卡片/表格/面板背景 |
| `--ink` | `#1A1A1A` | 主文字 + 主按钮底 + 激活态（"黑"即本主题的"品牌色"） |
| `--ink2` | `#767676` | 次要文字、placeholder、meta |
| `--line` | `#E3E3E3` | 边框、分割线 |
| `--terra` | `#C2622B` | 功能强调：待办/待复核状态、热点 chip、警示 |
| `--ok` | `#5B7163` | 成功/已完成状态、正向趋势 |
| `--bad` | `#A1402F`（建议补充） | 存疑/失败状态（style-b 原型未定义，补朱砂色与整体协调） |

**色彩铁律**：
1. 界面 95% 是黑白灰，功能色只出现在**状态**上（pill、趋势箭头、待办圆点）；
2. 赭石 = "需要人处理"（待复核/待跟进/进行中警示）；绿灰 `--ok` = "已完成/正常"；朱砂 = "存疑/失败"；
3. 与用户端联动：管理端"已发布到官网"的标识可用用户端中棕 `#8B5E3C` 作为品牌呼应（可选）。

### 2.2 字体系统

| 用途 | 字体栈 | 说明 |
|---|---|---|
| 正文/标题 | `'Helvetica Neue','PingFang SC','Microsoft YaHei',sans-serif` | 全站无衬线（与用户端衬线形成"前台温文、后台干练"的反差分工） |
| 数据/编码 | `'JetBrains Mono','Consolas',monospace` | RSPU 编码、任务编号、价格、耗时、统计数字、URL/接口名 |

**字号阶梯**：页面标题 22~34px（视层级）/ 区块标题 15px/700 / 表格正文 12~13px / meta 11px / 统计大数 26~30px（monospace）。

### 2.3 圆角、边框与密度

| 项 | 值 | 说明 |
|---|---|---|
| 圆角 | 6px（卡片/表格容器）、3~4px（小元素）、999px（tab 胶囊） | 比用户端（16px）硬朗，工具感 |
| 边框 | 1px `--line`，白卡 + 灰边为主，少用阴影 | hover 时边框加深到 `#B5B5B5` 代替阴影 |
| 表格行高 | padding 11~12px | 高密度；斑马纹可选，hover `#FAFCFF` |
| 页面宽度 | max-width 1360px，padding 24px | 比用户端更宽，服务宽屏 |

### 2.4 状态 Pill 规范（全站统一，与后端状态值一一对应）

| Pill | 样式 | 后端值 |
|---|---|---|
| 已完成 / active / 已确认 | 绿灰底 `#E8EFE9` + `--ok` 字 | `active` / `已确认` |
| 待复核 / 待跟进 / 进行中 | 浅赭底 `#F7E9DF` + `--terra` 字 | `待复核` |
| 存疑 / 失败 | 浅朱砂底 `#F5E4E1` + 朱砂字 | `存疑` |
| 信息（类目、置信度"高"） | 灰底 `#F0F0F0` + `--ink2` 字 | SF 沙发 / TB 茶几等类目 chip |

**纪律**：review_status 中文值（已确认/待复核/存疑）、status 小写英文（active）——前后端 pill 文案与数据库值严格一致，不做二次翻译。

## 第三章 · 工作台首页区块级详解

工作台首页 = 运营每天的第一屏，自上而下 6 个区块：

### 区块 1 · 顶栏 Header（52px，非吸顶大 Header）

- 结构：黑色方块 logo 标（R）+「RSDP 工作台」｜ 横向导航（首页/录入/产品库/方案/报价/订单/工厂/统计，激活项黑底白字胶囊）｜ 右侧 monospace 账号（admin@rsdp · ADMIN）
- 与现有工程差异：现有 web/ 工程为侧边栏布局——**保留侧边栏亦可**，style-b 的顶栏适合扁平结构；二选一，不建议混用。推荐：侧边栏（承载更多菜单：用户端官网 CMS、AI 能力、系统配置），皮肤按 style-b。

### 区块 2 · 页头 Hero（极简版）

- 左：monospace kicker（DASHBOARD / OVERVIEW）→ 34px 标题「产品数字化工作台」→ 副文案（录入 → 识别 → 搭配 → 报价 → 订单）
- 右：主按钮「+ 新品录入」（黑底）+ 次按钮「Excel AI 导入」（白底描边）
- 动态问候行（建议补充）：「早上好，明焕 · 今天有 3 个户型分析待复核、12 条新留资」——一句话聚合全站待办

### 区块 3 · 统计带 Stats Band（4 格，通栏分隔线式）

- 内容：产品总数 RSPU（1,286，+32 本周）/ 工厂报价 RSKU（3,514）/ AI 识别通过率（96.2%）/ 本月订单金额（¥18.4万）
- 样式：数字 26px monospace/700，标签 12px 灰，趋势小字绿（+）/赭（−）
- 建议补充第 5 格：**今日留资线索**（官网入口上线后的核心漏斗顶部指标）
- 接口：新增 `GET /api/v1/dashboard/summary` 聚合（避免前端调 5 个接口）

### 区块 4 · 产品库 · 最新入库（卡片流 + 品类 tab）

- 区块头：标题 + 品类胶囊 tab（全部/沙发/茶几/柜类/座椅，激活黑底）
- 卡片（4 列）：产品图（4:3 灰底占位）→ 名称+价格（monospace）一行 → `编码 · 尺寸` monospace meta → chip 行（风格/材质/报价×N——赭色热点 chip）
- 「报价×N」chip 是 RSPU→RSKU 三层模型的可视化：一眼看出该款式有几家工厂报价
- 点击卡片 → RSPU 详情页

### 区块 5 · 识别任务队列（表格）

- 列：产品 / 品类（SF 沙发）/ 来源（图片录入 · Excel AI 导入 · PDF 导入）/ 耗时（12.4s mono）/ 编码（mono）/ 状态 pill
- 这是「真实恶心表格」容错治理成果的展示位：来源列让运营知道每条数据的录入通道，耗时列监控 AI 通道健康度
- 行操作：待复核行显示「复核」链接 → 进入复核详情

### 区块 6 · 右栏/下方辅助模块（建议补充，来源三版工作台原型）

| 模块 | 内容 | 优先级 |
|---|---|---|
| 今日待办 | 圆点分级列表（朱砂=紧急/赭=待办/墨=一般/绿=已完成）：存疑任务、待分配线索、迁移评审、Excel 治理剩余项 | P0 |
| 户型图分析 · 待复核队列 | 缩略图 + 任务号 + 识别空间数 + 客厅尺寸 + 置信度 pill（高/中/低）+ 状态（待复核/存疑） | P1（随户型链路上线） |
| 最新留资线索 | 客户/来源（AI 户型搭配/官网表单/设计服务预约）/意向/时间/状态 + 分配操作 | P1（随官网上线） |
| AI 搭配数据完备度 | 4 条进度计：客厅 RSPU 覆盖 68/80、风格案例 20/31、主图覆盖率 92%、场景图覆盖率 34% | P1（直接服务 AI 搭配的数据补齐决策） |
| 快捷操作 | 新建款式 / Excel 导入 / 上传 Banner / 发起户型分析 四宫格 | P2 |

## 第四章 · 核心业务页面规格

### 4.1 产品中心

**① 款式库 RSPU 列表**
- 表格列：主图缩略 / 编码（mono）/ 名称 / 类目 pill / 适用空间 / 风格 / 尺寸（mono，来自 rspu_variant.dimensions JSONB 渲染 `2200×950×880`）/ 报价数（→RSKU）/ 主图✓场景图✓ 资产状态 / 状态（active）/ review_status pill / 操作
- 筛选：类目树（category_dict 复合键 dict_type+dict_code）、空间（scene_dict）、风格、review_status、有无主图/场景图（补齐数据的核心筛选项）
- 批量操作：批量改状态、批量指派复核、导出

**② RSPU 详情/编辑**
- 三段式布局：左（图集：主图 is_primary + 场景图 + 细节图，拖拽排序）｜ 中（基础信息表单）｜ 右（变体 dimensions JSONB 可视化编辑器 + RSKU 报价列表）
- dimensions JSONB 不做裸 JSON 编辑，用结构化表单（宽/深/高 mm、座位数、材质）读写 JSONB

**③ 工厂报价 RSKU**
- 表格：款式编码 / 工厂 / 报价（mono，**AES 解密后仅管理端可见**）/ 报价日期 / 有效期 / 状态
- 权限：报价列按角色脱敏（非采购角色显示 `***`）
- 绝不出现在任何 `/api/v1/public/**` 响应中

**④ 录入中心**
- 三通道 Tab：图片录入（AI 识别填表）/ Excel AI 导入（「真实恶心表格」容错治理主战场：P0 剩余 6 项治理进度看板挂这里）/ PDF 导入
- 每条导入记录挂识别任务（区块 5 队列同款行结构），失败原因结构化展示

### 4.2 AI 能力

**① 户型图分析工作台**（新链路，详见《户型图空间搭配链路完整方案》）
- 三栏：任务队列（待复核优先）｜ 户型图画布（AI 框选的空间 bbox + 尺寸标注，可人工修正墙体/尺寸）｜ 识别结果 JSON 与置信度
- 复核动作：确认（已确认）→ 触发搭配方案生成；存疑 → 退回人工标注
- 表：floor_plan_analysis / floor_plan_room（**V34 迁移**，含 scheme.analysis_id 外键）

**② 风格案例库**：31 条种子（11 正向 + 9 反向，仅 LIVING_ROOM）的列表 + 正向/反向筛选 + 新增案例（图 + 风格 + 空间 + 元素拆解）

**③ 搭配公式**：style_matching_formula 的规则列表与启停；公式命中预览（选公式 → 实时跑出候选 RSPU）

### 4.3 用户端官网 CMS

- **Banner 管理**：platform_banner 列表（图 + 标题 + 跳转 + 排序 + 上下架）——对应用户端区块 3 Hero
- **内容区块**：platform_content 按区块类型分组（trio_cards / service_cards / room_grid / product_rail / inspiration / cta），可视化预览 = 直接渲染用户端区块样式（所见即所得）
- **案例管理**：platform_case（灵感瀑布数据源）
- **留资线索**：platform_lead 表格（客户/来源/意向/时间/状态/跟进人），分配与跟进记录；来源分布小图表（AI 户型搭配 / 官网表单 / 设计服务预约）

### 4.4 系统

- 用户权限（角色 × 菜单 × 数据脱敏规则，重点：RSKU 报价可见性）
- 参数配置（platform_custom_dict 维护：顶部工具条链接、服务卡文案等）
- 迁移纪律提示：**任何新迁移必须三处同步**（V-file + V1__init_db.sql + reset_db.sql）

## 第五章 · 组件抽象（基于 Naive UI）

| `<CompletenessMeter>` | NProgress 封装 | 数据完备度进度计（目标值/当前值） |

## 第七章 · 现有工程换肤落地路径

**原则：组件零改动，只换皮肤。** 三步：

1. **替换 tokens**：`web/src/styles/tokens.css`
   ```css
   /* 旧 → 新 */
   --rsdp-bg:#fafafa        → #f7f7f7
   --rsdp-primary:#2453fc   → #1a1a1a   /* 主色即"墨" */
   --rsdp-price:#ff0000     → #1a1a1a（mono 加粗）/* 促销场景才用 #c2622b */
   --rsdp-text:#243443      → #1a1a1a
   --rsdp-font-display      → 中文生效的无衬线栈；新增 --rsdp-font-mono
   ```
2. **Naive UI 主题覆盖**（n-config-provider themeOverrides）：primaryColor `#1A1A1A`、borderRadius 6px/3px、warningColor `#C2622B`、successColor `#5B7163`、表格行高与边框按 2.3 节；
3. **状态出口统一**：全站搜索散落的 status 判断，收敛到 `<StatusPill>`（4~6 处替换）。

预估工作量：**1~2 天**（不含新页面）。新页面（户型图工作台/线索/CMS 可视化）按第四章规格正常排期。
