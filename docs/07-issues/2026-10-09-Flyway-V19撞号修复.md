# 本地 CAD 与远程 Agent 的 V19 撞号修复

日期：2026-10-09。范围：本机开发库 `rsdp` 与尚未提交的 CAD 迁移。

## 原因与统一版本

远程 `main` 已发布 `V19__agent_floor_plan_binding.sql`；本地 CAD 工作区也占用了 V19，且开发库已执行本地 V19–V21。两个 V19 会阻断 Flyway 启动。保留远程已发布迁移，顺延本地未提交的三份迁移：

| 原文件 | 统一后的文件 | Flyway 校验和 |
|---|---|---|
| V19__floor_plan_scene_revision.sql | V20__floor_plan_scene_revision.sql | 1768759763 |
| V20__widen_audit_log_action.sql | V21__widen_audit_log_action.sql | 205567900 |

三份文件仅改名，内容逐字节保留，包括原始版本注释。远程 Agent V19 内容亦保持不变。历史文档中的 CAD V19/V20/V21 对应上述旧编号，当前数据库与 API 说明使用统一编号。

## 本机开发库恢复

1. 备份完整开发库及 `flyway_schema_history`；运行 `mvn clean package`，清除 `target/classes` 中旧名资源。
2. 停止现有后端。事务内锁定迁移历史，验证三个原版本、脚本名、校验和及成功状态均精确匹配，且不存在 V22；仅将三条历史的 `version`、`script` 改为统一编号。原校验和、执行顺序、描述与成功状态保留。
3. 一次性以 `SPRING_FLYWAY_OUT_OF_ORDER=true` 启动，允许 Flyway 补执行尚未应用的 Agent V19。该迁移记录为 installed_rank=23、checksum=-1122343598、success=true。
4. 使用默认配置重新启动，Flyway 成功校验 23 份迁移，当前水位为 V22，无待执行迁移。乱序选项未写入项目配置。

这是已确认本机历史的专项校正，不能用于迁移内容或校验和不同的环境。已有远程 Agent V19 的环境无需改历史，后续正常执行 CAD V20–V22；全新数据库从 V1 顺序执行即可。

本机恢复材料在 `.git/codex-migration-20261009/`：完整数据库 `rsdp-before-version-reconcile.dump`、历史备份 `flyway-history-before.sql`、原始三份迁移、带事务与前置校验的 `reconcile-dev-history.sql`、重启前日志。恢复时必须保持迁移文件与历史一致。
