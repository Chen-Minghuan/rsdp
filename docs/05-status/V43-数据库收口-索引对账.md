# V43 数据库收口：索引对账表

> 比对范围：`database/V1__init_db.sql`（全新初始化基线）+ `V2~V40` 全部增量迁移 + `database/reset_db.sql`（DROP + 全量重建，含与 V1 完全镜像的 CREATE INDEX）。
> 产出日期：2026-09-05。状态列含义：**保留** / **V43 新增** / **V43 删除（冗余）** / **V43 修改**。
> 来源列写法：`V1` 表示当前基线中的行号；`（并入自 Vx）` 表示该对象最初由增量迁移引入、后并入 V1；`reset_db.sql` 与 V1 完全镜像，不逐条重复标注。

## 0. 路径分叉与已知差异（先读）

1. **idx_rspu_code / idx_rsku_code 仅存在于增量路径**：只在 `V20__business_code.sql:8,14` 创建，V1 没有（V1 只有 `rspu_code`/`rsku_code` 行内 UNIQUE，V1:24 / V1:303）。即"全新初始化"与"增量迁移"两条路径的索引集合**已经不一致**。V43 在增量路径删除这两个冗余索引（唯一性由行内 UNIQUE 的自动唯一索引覆盖），两条路径由此重新对齐。注意：V43 之后再手工重跑 V20 会把它们建回来（V20 保持历史原样不改）。
2. **reset_db.sql 不是纯 DROP 脚本**：它先 DROP 全部表（:14-82），再全量重建表和索引（:85 起），索引定义与 V1 镜像。因此 V43 的全部结构变更在 V1 与 reset_db.sql 两处同步修改。
3. **reset_db.sql 独有 `variant_code_counter` 表**（:216）：V1 也有（V1:122），两边一致，无分叉。
4. **factory_lead_time_rule 行内 UNIQUE 的自动约束名会被 PG 截断**：`UNIQUE(factory_code, category_code, material_grade_code, process_type)` 的默认约束名（76 字符）超过 PG 63 字节标识符上限，实际落库为截断名。V43 用 DO 块从 `pg_constraint` 动态查找并删除，不硬编码约束名。
5. **观察到但未处理（不在本次范围）**：`idx_product_match_rspu(rspu_id)` 是 `UNIQUE(rspu_id, style_code)` 的左前缀，理论冗余，但审计指令未列入删除清单，本次不动，留待下轮评估。
